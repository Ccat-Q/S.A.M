# SAM.OS 的空间、感知、关系和机器界面

用户明确要求第二轮 UI/UX 重构，保留第一版业务逻辑。这修订了第一版统一 Panel、双模式地图和通用 Inspector 的呈现决策。

可选方案：完整 WebGL / 3D 站体与房间提供更多自由视角，但显著增加运行成本、依赖、原生设备验证和制作成本；Canvas 原创站体与预渲染光学场景能在现有 Flutter 架构中形成清晰的视觉层，风险更小。本轮采用后者，原生视频适配器仍留给未来。

Relocation 首层只表达物理空间，Module Select 引导用户去 Camera，设备在舱段二级视图或独立 Network 可达。Camera 使用原创预渲染资产与现有 camera_targets，不增加虚构识别或硬件控制。两个原创场景作为八个模拟摄像机的显示资源，界面明确标识不是直播。

System Link 增加客户端符号序列，服务端原有 Scan → session-bound Link → versioned/idempotent command 是唯一权限依据。已知界面快速配对仅跳过视觉输入，不能跳过认证。机器界面按设备能力分型，共享安全控制提交器而不共享资产数据库布局。

Memory Ring 复用已经持久化的事件及统一 Node/edges 做只读关系投影。不新增独立记忆数据库、不伪造 AI inference、音频或录像；避免为视觉需求推倒后端模型。真正的长期知识存储与 AI 记忆构造仍需未来独立 ADR。

验证在 GitHub Actions：角色与并发协议原测试继续执行；新增错误符号不能提前发送 Link 的控件测试。模拟器联机链覆盖告警、模块、离线相机、Pair、专用电源界面、故障恢复、在线目标、独立网络、Memory 来源关系和模块二级设备层，并保留截图。保留缓存、并行构建和 14 分钟整轮终止线。

后续运行感迭代采用页面绑定的 Context Soft Keys，一级 Tab 只负责模块导航；底部操作分发不持有设备授权。与为每个模块再维护一份业务状态相比，保留单一 SystemStore、只增加短生命周期视图状态，控制与权限风险更低。站体、视频噪声使用独立 RepaintBoundary/CustomPainter，而不是每帧重建整个系统；降低运行开销并响应减少动态效果。实际 WebSocket 事件投影为有界显示队列，保持持久审计职责不变。


操作深度沿用 Shell 内的显示状态与页面回调，不引入独立路由栈：与路由迁移相比，现有 Flutter 页面状态与控制会话的风险更小，仍能明确收起操作层的一级导航。授权继续由 SystemStore 和服务端负责。镜头采用 Canvas 三角网格，而非引入 shader 编译链；原图和目标区域共用径向映射。Alert 历史复用 Scene JSON，一次性添加明确的 Mock 历史，不增加表或迁移，也不覆盖已有异常。Memory 的 CONSTRUCTED 是确定性关联投影，不能解释为模型推理。
