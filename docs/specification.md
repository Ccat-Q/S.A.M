# 第一阶段规格

## 目标与范围

面向最多五人在线的团队运维平台。单设施，服务端权威模拟，Flutter iOS 16+（iPhone / iPad）首发，Android 仅预留工程，Web 延后。中文与英文可切换。

必须完整实现：Shell、Overview、Relocation、独立 Network Map、Camera、Device System Link、Alerts、Logs 和只读 Memory Ring；配套登录、成员及显示设置。真实 AI、独立长期知识/记忆写入、Automation、Entity Tracker、Communication、摄像头和硬件接入不在本阶段。

## 权限

管理员：查看、扫描、连接、控制、确认告警、创建/禁用成员、修改角色、触发/暂停/重置模拟。
操作员：查看、扫描、连接、控制、确认告警。
观察员：查看与扫描；不得建立控制 Link 或执行写操作。

没有公开注册或默认密码。登录会话默认 24 小时，禁用成员或变更角色立即撤销其会话与 Link。首个管理员由交互式 CLI 创建。最后一个启用管理员不能被禁用或降级。

## 场景与控制

42 节点：8 CAMERA、12 DEVICE（4 POWER / 4 DOOR / 4 LIGHT）、6 SENSOR、4 SERVER、3 ROBOT、5 NETWORK、4 MODULE。SRV-01 为 AI CORE 的模拟主机，不表示已接入语言模型。

空间归属、通信链路、供电依赖、摄像头目标分别存储。设施地图用于观察位置，网络地图用于分析依赖，均引用相同 Node ID。

遥测每两秒更新，使用确定性波形；故障场景由管理员触发：DEV-01 输出故障、CAM-02 信号丢失、SEN-03 温度过高。没有不可复现的随机严重告警。

观察 → 扫描身份和能力 → 客户端短 Pair 序列（已知界面可快速配对）→ 服务端授权 Link → 显示设备面板 → 提交命令 → 显示结果。Link 默认闲置五分钟到期。高影响操作（断电、重启、恢复故障、网络连接切换）需显示所有依赖节点并二次确认，凭证 60 秒失效。

控制包括：电源、门禁、灯光亮度、摄像头 pan/tilt/zoom、适用节点的诊断、重启、故障恢复、网关连接切换。上游不可用时无法远程连接下游；仍可连接上游恢复供电/网络，禁止伪造可用控制通道。

多人 Link 非独占。命令携带状态版本与成员范围内的幂等 key；旧版本拒绝，重复请求返回原结果。遥测波动不推进控制版本。命令结果有 SUCCEEDED/FAILED，不把网络超时视作执行失败；超时按 key 查询，无法确定时提示结果未知。

## 告警、恢复与留存

ACTIVE → ACKNOWLEDGED → RESOLVED。ACK 记录接手人而不清除故障；故障条件消失自动解决，解决后再次故障生成新告警。场景重置以明确原因解决现有告警并保留历史。

断线保留最后状态，显示数据过期，禁用控制并清除客户端 Link。重连补齐事件/获取快照，重新建立 Link。服务重启、登出、连接中断、成员权限变化、场景重置使有关 Link 失效。

服务重启保留节点、告警、账号与命令记录。运行日志 30 天，审计/告警/命令 90 天，配置可调整。场景重置不删除账号与审计。

## 交付

仅 GitHub Actions 编译及自动化验证。产物是未签名 IPA、Ubuntu 镜像归档、Compose 包和部署说明。不自动部署或改 DNS，不承诺未签名 IPA 可以直接在普通 iPhone 上安装。

## 第二轮 UI/UX 修订

按用户明确要求，以开放黑场、空间站线框、真实感预渲染 Camera、设备专用终端和径向 Memory 关系场替代统一 Dashboard Panel。现有 42 个 Node、权限、模拟、状态、设备控制及保留策略不变。Memory 首轮只读投影来自现有持久化日志和 Node/edges；不表示已实现 AI、录音、录像或新的长期记忆服务。详见 design.md 和 ADR 0005。

运行感迭代保持上述视觉，底部改成上下文 Soft Keys；增加有实际事件依据的 bounded queue、非对称设施几何、轻周期绘制、告警待机监测及老旧 CCTV 效果。手动 target lock 属于客户端选取行为，不是自动实体追踪。所有已有管理入口保留在 SYSTEM / COMMAND 索引中。
